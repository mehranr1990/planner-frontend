## A. Locked decisions that every new page must reuse (the "do not change" list)

### A1. The notch (Signature card) — exact, built, locked
- Component: `SignatureCard` (`src/design-system/surfaces/signature-card.tsx`) + `notch-path.ts`. A 32px-radius card with a **sculpted top inline-end corner**: top-right in LTR, **top-left in RTL**.
- Implementation: a CSS `mask` (fixed-size gradient tiles) on first paint, then a measured `clip-path: path()` from a `ResizeObserver`; the action buttons live in a sibling layer (never clipped). RTL mirrors x and arc sweep flags.
- Presets: **desktop notch 64×64, fillet 28, button 54px**; **mobile 56×56, fillet 24, button 46px** (`preset="auto"` switches at Tailwind `lg`=1024px); **focus preset 72×72, fillet 30, button 56px**; **double notch 112×60 with two 48px buttons** (used when a card has two closely related actions: secondary first, primary at the corner).
- **A notch is NEVER empty.** It holds exactly one real circular contextual action, or two (double notch). Never invent an action to fill it. (The older board text "or stays empty" was overruled by the owner.) Even where a board draws an empty corner, a real action is placed and the deviation is reported.
- Max 3 signature cards per desktop viewport (1–2 on mobile). Only one may be volt. Tones: `surface`, `deep` (`#0E6B57` light / `#173A31` dark), `volt` (live/now only), `scope-soft`.
- Items inside families (rows, KPI tiles, board cards, people, list rows, inputs, filters, settings groups, sheets, toasts) are **never notched**.
- Where notches are used today (keep these actions): Timeline card → Add block · Now card → Mark done · Focus entry → Start focus · Overview Today hero → Open My Day (+ reused Now card) · Task Detail header → Complete/Reopen · Inbox Process card → Skip → · Brain Dump page → Voice capture · Focus screen → Pause/Resume/Start (focus preset) · Shutdown Tomorrow card → opens tomorrow in My Day · Goals selected-goal panel → Edit · Habits selected-habit head → Check today · Finance balance card → Add expense · Journal composer → Prompt me · Insights headline → Why this? · Weekly Review Story card → Share summary · Calendar selected-event panel → Open/Close (double notch). **Tasks List/Board, Settings: no signature card.**

## C. Personal gaps register — what is built only as UI/mock vs. truly operational

Use this to avoid confusing "looks finished" with "works end-to-end":
- **Everything is mock-backed and in-memory** (resets on reload); no real persistence except cookies (settings) and `localStorage` (Focus timer state, Overview slot dismissals, Calendar layer toggles, some UI flags).
- **UI-only / placeholder:** all authentication (Google, email/password, magic link), account deletion/export, Settings rows marked "Not available yet" (reduced motion, density, time format, reminders, free slots, month start, categories, nudges, import/export, archive), journal/finance **locks** (no PIN/biometric — view-level toggle only), notifications/bell content, Voice capture needs the browser Web Speech API (unsupported/denied states handled), Share summary uses the system share sheet or copies text.
