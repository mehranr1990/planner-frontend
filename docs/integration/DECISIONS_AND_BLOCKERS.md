# Decisions and blockers

No credentials, cookies or tokens belong in this file.

## Approved / inherited decisions (keep)

- Cookie sessions only; no token storage; Origin never set from JS; quoted ETags verbatim; one Idempotency-Key per intent, same key + body on lost-response retry.
- 409 handling: refetch the aggregate, re-send the same intent once, then surface.
- Unsupported fields are refused (`RepositoryError("unsupported")`) and shown as "Not available yet" — never kept in memory or faked.
- Partial saves are reported (`RepositoryError("partial")`) with a Retry for the failed fields.
- Live mode is hybrid: non-integrated modules stay on the mock adapter; integrated modules never fall back to mock on failure.
- Transport is Gregorian/UTC; Jalali is display only; planner zone = account `/me/settings` timezone.
- Per-phase mapping decisions for 00b–03: `docs/INTEGRATION_PROGRESS.md`.

## Phase 04 implementation assumptions (2026-11-11)

- A task on the timeline = TIME_BLOCK linked to the Task. The API never changes the Task for a block (calendar runbook), so `schedule`/`move`/`unschedule`/`restore` also write the Task's day/time/estimate; block saved + Task failed → `partial` ("time").
- Blocks whose linked Task is DELETED / CANCELED / SKIPPED are hidden from the timeline (the server keeps them; they reappear when the Task is restored). CANCELED blocks/events and all-day entries are hidden (no all-day lane in the UI).
- Moving a virtual occurrence of a recurring event is refused (`unsupported`) until the series flow is mapped.
- Block priorities on My Day stay `unsupported` (Day plan items are tasks only).

## Phase 05+ implementation assumptions (2026-11-12, need a live check)

- Revision ETags are built as the documented quoted revision (`"<revision>"`) from list payloads instead of an extra GET; a 409 reloads and re-sends once.
- Habits: no target → CHECKBOX/COUNT/"1"; target → QUANTITY with the unit upper-cased to an API code (shown lower-cased). Rest weekdays ⇄ DAILY / WEEKDAYS (ISO). INTERVAL rules other than 7 days show as daily. Paused habits show as active. "Pinned" (Overview ribbon) = first active habit (the API has no pin). Whether an entry write advances the habit revision is unknown; the 409 retry covers it. Editing days re-sends the original `startDate` with the default `effectiveFrom` (today).
- Goals: active = PLANNED/ACTIVE/PAUSED, completed = COMPLETED, archived = ABANDONED. New goals: horizon SHORT_TERM when the deadline is within 365 days else LONG_TERM; progressMode WEIGHTED with contributing milestones; a measure = one METRIC (baseline 0) selected on the goal. Area = Life area matched by title, created on first use. Task goal = `links/tasks` with contributes:false (one goal per task enforced client-side). Progress is always the server percentage. Free-text target is refused (no field).
- Focus: the P09 timer stays browser-run; each finished cycle is stored as a MANUAL time entry (actual end, focused length without pauses, so the start is end − focused). "Sessions today" = the day`s recorded entry count from `/productivity/summary`. Server-clocked `/focus/sessions` are not used (would need the timer UI to drive start/pause/resume/finish) — owner decision if wanted later.
- Journal: the day`s entry = the day`s daily check-in (CHECK_IN) + its linked mood. Energy low/medium/high ⇄ 1/3/5. The API entry has only one Markdown text, so "What went well", prompt answers and tags are stored as trailing `## Went well` / `## Prompt: <id>` / `## Tags` sections of it (user lines that look like these headings are backslash-escaped). FREEFORM entries and mood notes are not used. Range `to` is sent as the next day and filtered client-side (inclusive/exclusive not documented). Undo of a removed day creates a new check-in (history keeps the deleted one). **Owner may prefer dedicated API fields later.**
- Inbox: untriaged = INBOX, archived = ARCHIVED, processed = TRIAGED (read only). The UI creates the destination itself, so server triage (which would create a second target) is not called; processed / dropped are stored as ARCHIVED and shown as archived after a reload. Snooze: no API state → unsupported. Capture origin (voice/share/brain-dump) is not stored (type NOTE for quick notes, else DRAFT).
- Finance: Toman ⇄ IRR ×10 as exact decimal strings; only IRR is read (other currencies, transfers, adjustments are not listed but count in the account balance). Wallet = oldest active IRR account; the first write creates an account named "Personal" when none exists, and the seven UI categories as EXPENSE categories by English name (other API categories read as "other"). One `note` field: first line = title, rest = note; no time = local 00:00. Posted money is immutable: edit = `correct` (new id), delete = `reverse`, undo = a new posting (new id). Month budget = period snapshot of the one MONTHLY·JALALI budget without category (created by Set budget); months without a period show the budget limit only if not ended. Savings card = first active IRR savings goal (total progress, not per month). Upcoming bills = unpaid EXPENSE occurrences in the next 90 days.
- **B3 — Brain Dump has no backend model.** The contract has captures and notes but no per-day page with ordered lines, sort tags or strike. Brain Dump stays on the mock adapter in live mode (browser-only data); "send to Inbox" is refused there. Needs a backend model or an owner decision (e.g. one Note per day).
- **B4 — Insights patterns have no contract source.** `/insights/*` returns generic metric cells per day/week/month; P15 needs an hour-of-day focus distribution (+ interrupted sessions), time per context, mood/energy signals and habit-vs-mood (Journal/Mood analytics are rejected by the API), and estimate accuracy per category. In live mode the header shows real active days (days with tracked time), there is no headline/highlight, and each tab shows its error state (`unsupported`). Needs backend metrics or an owner decision to compute client-side.
